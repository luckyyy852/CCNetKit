# 接入已有网络，避免相互接管

本流程用于使用者自己的机器。整理与生成私人配置时先只读；安装管理窗口不代表允许替换原 VPN、系统代理、网卡 DNS、电源策略或网站的中转。

## 1. 记录现状与归属

在本机核对以下内容，输出留在仓库外，不上传完整结果：

```powershell
Get-NetAdapter | Select-Object Name,InterfaceDescription,Status,ifIndex
Get-NetTCPConnection -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
Get-NetUDPEndpoint | Select-Object LocalAddress,LocalPort,OwningProcess
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' |
    Select-Object ProxyEnable,ProxyServer,AutoConfigURL
netsh winhttp show proxy
Get-NetRoute -DestinationPrefix '0.0.0.0/0','::/0' -ErrorAction SilentlyContinue
```

同时查看所选客户端的 TUN / 系统代理开关、内核路径、持久配置入口和启动任务。命令只能提供线索，不能仅凭进程名判断哪个客户端实际接管。代理环境变量只核对是否存在与设置来源，不打印可能包含账号密码的值。读取敏感文件只提取必要字段，不做整机配置导出。

在私人目录记录：目前谁管理 TUN、系统代理与 DNS；端口归属；原有业务例外；需要保持不变的文件路径和哈希。网站中转常在项目环境变量、SDK 配置或服务端，不因为装了分流工具就更换 API 地址或密钥。复用的配置先做一份有明确归属的私人备份。

## 2. 根据已有环境选择一种接入方式

| 现状 | 采用方式 | 不应做的操作 |
| --- | --- | --- |
| 已有正常 Mihomo TUN | 复用其 API 与持久配置，安装工作台；规则通过客户端持久覆写或明确的独立 JSON 管理 | 另开第二个日常 TUN；编辑会被订阅更新覆盖的临时 YAML |
| 已有其他 VPN / TUN | 优先保留，只增加应用内显式代理；确需换日常接管时安排一次可恢复的切换 | 同时打开两个自动路由，让它们争抢 DNS 和默认路由 |
| 原客户端只设置系统代理 | 先复用其代理；增加软件例外时明确由谁管理系统代理 | 让两个客户端循环写同一个系统代理开关 |
| 已有软件专用代理或网站中转 | 将它作为已有业务例外登记，核对完整调用链，再添加新规则 | 把所有软件统一覆盖为新端口；清空项目环境变量 |
| 没有可用代理 | 按 [Mihomo 安装](mihomo-setup.md) 先建立显式代理，再开启一个日常 TUN | 用尚未验证的节点直接接管全网 |

专用核心可与日常核心并存，但专用核心不开 TUN、不开系统代理、不开 DNS 监听，使用自己的回环端口；不要复制日常 TUN 配置后直接同时启动。若日常 TUN 会再次截获专用核心，按实际核心的接口绑定 / 排除机制设置，验证专用核心的出站；不能仅凭多开了一个端口就声称已分离。参考 [Mihomo 出站绑定](https://wiki.metacubex.one/config/proxies/)。

## 3. 接入工作台与业务例外

在私人 `settings.json` 中，只将日常配置列入 `Profiles`；专用配置、项目环境文件放入 `ProtectedFiles`。把必须保留的完整规则放入对应的 `ProtectedRules`。这是对本工具操作的保护，不能限制其他客户端修改这些文件，也不是应用读取秘密的权限控制。

新增软件规则见 [按软件分流](application-routing.md)。规则顺序需按用户目标安排：必须保持的业务例外与专用入口在通用规则之前；软件整进程走某节点会覆盖它访问的多个域名，不能在不了解业务时把全局 `node.exe`、`python.exe` 或浏览器设为固定出口。

工作台的域名按钮只增加或撤销自己管理的 `DOMAIN-SUFFIX` 例外，不负责创建进程规则。早于它的进程规则仍可能优先；显示“域名已设直连”不能替代实际路线验证。

## 4. 逐步切换与撤回

1. 在不抢占现有监听端口的条件下校验新配置，先测试显式代理。未验证前保留原通道与原客户端入口。
2. 实施已选定的接入方式。若必须换 TUN，先确认原配置备份和恢复入口，再停止原来的接管方并启动新的一个；不能承诺切换期间连接完全不中断。已有正常 TUN 能复用时不切换。
3. 在目标应用产生新请求，核对连接路线、规则命中和实际操作结果。分别检查国内网页、外网、图片上传、网站中转，以及原有专用保护是否仍在。
4. 失败就回退本次修改的配置、监听器、覆写或启动任务，恢复原接管方。不能删除其他规则、结束同名的全部核心或恢复整机出厂网络来处理局部失败。

实际受保护应用的退出、停用专用代理或换网测试放在其工作已保存时执行，使用者事先明确知道会断开该应用；不为了测试去中断无关软件。见 [Claude Code 保护](cc-protection.md)。

## 5. 开机与待机

为每个角色只保留一个明确的启动入口。已有客户端管启动就复用它，不重复安装日常启动任务。专用锁定状态必须持久保存，开机、登录或待机唤醒都不能自动清除锁定。

完成后在使用者机器验证一次重启和一次待机恢复：日常网络与专用连接分开判断；真正的物理换网可锁定专用连接，普通请求超时不能触发全网重启。不把“进程在线”报告成“所有应用都联网”，也不未经验证承诺隔夜绝不会断。
