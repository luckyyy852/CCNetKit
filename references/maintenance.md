# 维护边界

附带窗口不自动修复全网、不安装应用隔离。先核对当前核心、任务、系统代理和专用保护，再按当前授权实施修复。

待机后断网要结合电源/网卡事件、进程退出、DNS、透明 TUN 和显式代理路径。监听端口存在或进程存活不代表原生应用联网正常。

加入健康恢复时，不因单次超时重启；使用连续失败、时间门槛、第二参考路径和冷却期。上游与备用同样失败时不反复重建 TUN。尊重手动关闭；关闭睡眠、改 DNS、安装启动任务不是安装窗口的隐含步骤。

TUN 重建可能触发已有专用守卫，仍按原策略锁定、手动恢复。不能为了测试通过而忽略真实换网或自动解锁。

上传排查需保留进程、请求与时间证据。HTTP 根路径返回 400 只证明相应网络层可达，不能当作上传成功；不根据其他机器的经验全局禁 IPv6、替换 DNS 或关闭嗅探。

代理环境变量、固定出口、守卫存活都不单独证明应用无法直连。严格防直连需要在目标环境验证隔离/防火墙和实际启动入口。通用部署、合成模板与可选守卫见 [Claude Code 专用保护](cc-protection.md)，其中区分采样守卫和隔离边界；脚本不自动安装第三方隔离，也不替代目标机器的验收。

软件例外见 [按软件分流](application-routing.md)，已有 VPN / 系统代理的归属与撤回见 [兼容流程](network-compatibility.md)。不要因本工具新增流程就迁移一台已正常工作的机器；只有当前任务要求的配置才实施。

## 更新与移除

更新技能时只替换公开技能文件；不会自动升级已安装的管理程序，也不重置网络。现有安装器只支持新目录，拒绝覆盖旧安装。需要更新管理程序时，由 AI 先确认系统与设置格式兼容，关闭管理界面并在私人目录备份将被替换的程序文件，再仅更新通用程序和帮助文件；保持安装目录权限，不覆盖 settings、routes、data、凭据、备份、守卫或锁定状态。验证失败只恢复本次替换的程序，不能用旧网络配置覆盖用户的新改动。

移除技能只移除技能本身，不会卸载已运行的内核、TUN 或管理程序。移除管理程序前记录其私人设置和受管规则归属，不删除仍在使用的节点配置、域名记录或网站资料；需要撤回网络时按实际接入方式单独处理。专用保护的撤回沿 [专用保护说明](cc-protection.md#7-撤回与卸载)，不能用删除安装目录代替。
